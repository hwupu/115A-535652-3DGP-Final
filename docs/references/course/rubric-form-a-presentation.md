# Form A — Presentation, slides, live demo, source check

Source: `3DGP_Form_A_Presentation_and_Slide.docx`. The paper form is filled in manually. This file only records the rubric.

**Presentation score = individual (30%) + group (70%).**

General rules: show every finished item in the ppt, bring the source code, do a live demo in addition to the videos, and finish the game during the live demo. The teacher also gives an overall impression (clarity, consistent slide format): Excellent / Above average / Below average.

## Procedure
| Stage | What | Notes |
|---|---|---|
| 1. Oral presentation | All members present the slides | **Each member must present at least 3 minutes** |
| 2. Live demo | Play and **finish** the game while narrating the gameplay; show all finished items | Prepare **"god" keys** to speed up the demo |
| 3. Q&A | TAs and others ask **each member at least one question** | |
| 4. Source check | TAs check the source code to confirm the claimed items | Show the code and answer questions |

## Individual score (max 100; +2 bonus per item done well, up to +10)
| Item | Max | Criteria |
|---|---|---|
| Group coherence | 5 | The first presenter introduces all members by name. Each speaker introduces the next speaker by name. |
| Non-verbal communication | 15 | No note reading, eye contact, body gestures |
| Verbal communication (English +10%) | 15 | Clear voice and tone, enthusiasm, volume, clear language |
| Time control | 65 | Covers the assigned slides smoothly in the right amount of time. Not every slide has to be presented. |
| **Penalty:** Q&A | −20 | Can't answer questions |
| **Penalty:** too short | −50 | Presentation of **≤ 3 minutes** for that member |

## Group score (max 100)
| Required slide item | Max | Criteria |
|---|---|---|
| Title page + introduction | 5 | Introduce the members and the game |
| Teaser demo video | 5 | Highlights gameplay and content, clear video, sound effects and BGM, **1–3 min** (a bit longer is fine) |
| ≥ 4 representative images | 5 | Attractive images |
| Game story | 5 | Background, **≥ 80 words** |
| Game design | 5 | Game type and goal, **Hero's Journey** in the design, game controls |
| System architecture diagram | 5 | **≥ 10 components** |
| Game level explanation | 10 | Per level: gameplay video (~30 s), design explanation, **≥ 2 images**, clear scene layout, **subgoal** |
| Sound effects | 5 | Play the sounds and show the triggering events in images or videos |
| Particle systems | 5 | Must be shown with **video clips** |
| Technical session (show source code) | 10 | **≥ 3 techniques**; explain one with its source code (e.g., game AI, steering, physics simulation, collision handling) |
| Finite state machines | 5 | Show **≥ 3 FSMs**, explain the workflow, explain one in detail |
| Workload distribution | 10 | Work items per member, **lines of code per member**, contribution of each member |
| Milestones | 5 | Project milestones; how implementation progressed |
| Conclusion + acknowledgement + reference list | 5 | What we did, what we learned |

## Group bonus and penalties
| Item | Points |
|---|---|
| Inconsistent font types or sizes | −20 |
| More than 50% of slides have no image or video | −20 |
| Each missing required item above | −5 each |
| At most 5 slides without any image or video | +5 |
